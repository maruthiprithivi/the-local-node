# Leak check: LFM3-1.7B tool-loop kit

Scope: every file in this folder and every file and directory name. Checked on 2026-11-10 (UTC+8) before handoff for publication.
The search terms are described by category, not listed literally, so this file does not reintroduce them.

**Verdict: PASS.** No secrets, credentials, private host or network identifiers, personal data, internal agent or message IDs, or private absolute paths.

## Tools and patterns

- A case-insensitive `grep -rnIiE` over contents and a `find` over names (relative paths) for:
  - the test hosts' machine names and short host IDs;
  - the owner's local username and home paths, plus `$HOME` and `/home/` paths;
  - internal workspace and bench tree names, internal harness and suite names, the host memory-slice name, internal container names and internal job and launcher names;
  - tailnet, Tailscale and `.ts.net` names;
  - private IPv4 ranges (10/8, 172.16/12, 192.168/16, 100.64/10);
  - e-mail addresses;
  - token prefixes (GitHub, OpenAI-style `sk-`, Hugging Face `hf_`, Slack `xox*`, AWS `AKIA`) and `BEGIN … PRIVATE KEY`;
  - 1Password, `op://` and vault references;
  - `password`, `secret`, `api_key`, `token=`, `bearer`, `authorization` and `cookie`;
  - `.env`, SSH and key-file names;
  - UUIDs, internal chat and turn IDs, internal agent and bot names, inbox and Slack references, and canary markers.
- A separate pass for hex strings of 32 or more characters and base64-like strings of 40 or more characters.
- A UTF-8 decode of every file to catch binaries. A check for symlinks.
- A mock run of `scripts/toolloop.py` against `scripts/mock_server.py`. It completed and reported the expected `repeat_earlier_call` break.

## Remaining matches (reviewed, all public or benign)

- `github.com/maruthiprithivi/the-local-node`: the public repository link.
- `getent passwd` in `docker/Dockerfile`: a standard command that renames uid 1000. No password.
- "hidden tests" and "DSpark" in RESULTS.md: test design wording and the public name of the speculative decoder used by the idle 27B server.
- Long hex strings: only the public sha256 values of the three official GGUF files and the public Hugging Face repo commit SHA.
- `/data/...` paths inside `results/tool-loop/*.summary.json`: synthetic arguments generated by the driver from the seed, not real paths.
- Exec bits are set on the four `.sh` scripts on purpose.

- `scripts/analyze.py`: verbatim.
- `scripts/mock_server.py`: verbatim plus a 2-line usage header.
- `scripts/client.py`: verbatim plus a generic 1-line docstring. The internal test label was removed.
- `docker/Dockerfile`: verbatim (public base image).
- `scripts/run-toolloop.sh`, `run-toolloop-part2.sh`, `bench-decode.sh` and `download-models.sh` were rewritten from the scripts actually used, with the same docker flags, llama-server and llama-bench arguments, seeds, contexts, memory gates and order:
  - Hardcoded personal bench paths became `MODEL_DIR`, `LLAMA_DIR`, `CUDART_DIR`, `OUT_DIR` and `OUT_BASE`.

  - `bench-decode.sh` keeps parts A and B only. Part C needs the unpublished harness.

- `results/decode/llama-bench-{Q4_K_M,Q8_0,BF16}.json` and `llama-server-c1-Q8_0.json`: raw llama-bench output and decode client output, verbatim. Model paths inside are container paths (`/models/...`).

## Files excluded and why

- Per-turn run JSONs and console logs (`run-c*-s*.json`, `*.console.txt`): full per-turn transcripts including model reasoning. They are not needed, because the chains regenerate from the seed. Left out by default as raw logs.
- llama-server logs, `tl.log` launcher logs, `mem.csv` and `gpu-*.csv`: these contain the host cgroup and service names, host process IDs and co-resident workloads. The memory figures are in RESULTS.md.
- The smoke run (not counted in the results), its logs, `toolloop.v1.py` (superseded) and the unit journals.
- Part C: the coding-check matrix, harness adapter, per-run artifacts, agent home directories (`auth.json`, settings), session logs, git objects and the OpenShell config. These belong to an unpublished harness and task suite and include sandbox credential files and canaries. Part C results appear only as aggregates in RESULTS.md.
- The parts A/B launcher logs, the duplicate-prep and aborted-attempt logs, the relay script (part C only) and the private report (`t7-lfm3.md`). The private report has host names and internal paths.
- Nothing from the Super-agent test (injection or reach material) is included.
