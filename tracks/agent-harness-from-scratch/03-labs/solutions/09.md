## A minimal approach

Create a fresh temporary world for each mode, then inspect artifacts directly. A dry-run may produce a proposed-action record, but do not assert that a file was written. Semi mode ends with pending identity and approval_required. Autonomous mode still denies outside targets and action-budget overflow. Keep the approval-dependent action unchanged when resuming; a different event or arguments need a new approval.

## Test the explanation

Start from the lesson's successful fixture, then change exactly one input to reach its deliberate failure. The successful result should satisfy:

Dry-run has zero effects; allowlisted autonomous action changes only its target; semi reports approval_required and can continue only with an exact approval.

The failure must demonstrate:

Choose an artifact outside allowed scope or exhaust action count. No file should be created. In semi mode, an unapproved action must remain pending rather than be reported completed.

Use pytest's `tmp_path` for mutable files/databases and a recording fake for provider/handler calls. Inject time instead of waiting. Verify a negative assertion about the boundary, such as zero executions or unchanged bytes, as well as the visible error. Never substitute “the model said it was safe” for an assertion on host policy or actual state.

def test_dry_run_is_preview_only():

## Exercise extension reference

Keep this extension in your learning branch. The fragment demonstrates the minimal additional seam; integrate it only after the baseline test and deliberate-failure case are understood.

```python
from course_harness.tools import FixtureWorld, scenario_tools, Policy

def handle_event(event, policy, world, *, action_limit=1):
    if action_limit < 1:
        return {"status": "budget_exhausted"}
    if event.get("kind") != "daily-summary":
        return {"status": "ignored"}
    arguments = {"name": "daily-summary", "text": "synthetic event summary"}
    tool = scenario_tools(world).prepare("record_artifact", arguments)
    decision = policy.decide(tool, arguments)
    if decision != "allow":
        return {"status": decision, "arguments": arguments}
    return {"status": "completed", "result": tool.execute(arguments)}

def test_event_modes():
    event = {"kind": "daily-summary"}
    for mode, expected in [("dry_run", "preview"), ("semi", "ask"),
                           ("read_only", "deny"), ("autonomous", "completed")]:
        world = FixtureWorld()
        policy = Policy(mode, frozenset({"record_artifact"}))
        result = handle_event(event, policy, world)
        assert result["status"] == expected
        assert bool(world.artifacts) is (mode == "autonomous")

# When multiple events share a run, move the action counter into run state.
# A per-handler fresh counter would evade the overall action budget.
```
