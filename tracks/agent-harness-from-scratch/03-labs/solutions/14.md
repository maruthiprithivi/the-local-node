# Lesson 14 reference solution

Read [the lesson](../lessons/14-resident-lifecycle/README.md) first. This reference explains the smallest intended change in the shared package; it is not a second copy of the harness.

## A minimal approach

Persist event identity before acknowledging admission. Use the queue's capacity decision rather than silently dropping old tasks. A duplicate after restart should reuse the documented identity result. After lease expiry, inspect action state before allowing repeat execution. Persist human stop and read it on startup and before dispatch; retain the backlog for inspection. Test each scenario with the same worker/controller and independent disposable fixtures. Dead-letter work remains inspectable rather than being deleted.

## Test the explanation

Start from the lesson's successful fixture, then change exactly one input to reach its deliberate failure. The successful result should satisfy:

Logical duplicates produce one admitted task within scope; overflow is visible; shutdown/restart preserve work and human stop; unresolved effects are inspectable.

The failure must demonstrate:

Create an event storm and a crashed claimed task. Capacity must remain bounded. Restart after human stop must claim/execute no new work even if the queue still contains tasks.

Use pytest's `tmp_path` for mutable files/databases and a recording fake for provider/handler calls. Inject time instead of waiting. Verify a negative assertion about the boundary, such as zero executions or unchanged bytes, as well as the visible error. Never substitute “the model said it was safe” for an assertion on host policy or actual state.

## A concrete test to adapt

This source example uses the delivered API. It is a starting point for a learner test, not a claim of execution. Save it in your own test file and extend its failure assertions on an approved development machine.

```python
from course_harness.persistence import DurableStore
from course_harness.resident import ResidentQueue, QueueFull

def test_dedup_capacity_and_stop_survive_restart(tmp_path):
    import pytest
    path = tmp_path / "queue.sqlite"
    store = DurableStore(path, clock=lambda: 100)
    queue = ResidentQueue(store, capacity=1)
    first = queue.enqueue("event-1", {"scenario": "coding"})
    assert queue.enqueue("event-1", {"scenario": "coding"}) == first
    with pytest.raises(QueueFull):
        queue.enqueue("event-2", {"scenario": "sre"})
    queue.stop()
    store.close()
    reopened = DurableStore(path, clock=lambda: 101)
    recovered_queue = ResidentQueue(reopened, capacity=1)
    assert recovered_queue.claim("worker-1") is None
    assert recovered_queue.inspect()[0]["id"] == first
    reopened.close()
```

## Exercise extension reference

Keep this extension in your learning branch. The fragment demonstrates the minimal additional seam; integrate it only after the baseline test and deliberate-failure case are understood.

```python
def test_expired_claim_is_uncertain(tmp_path):
    from course_harness.persistence import DurableStore
    from course_harness.resident import ResidentQueue
    time = {"now": 100.0}
    store = DurableStore(tmp_path / "leases.sqlite",
                         clock=lambda: time["now"])
    queue = ResidentQueue(store, lease_seconds=5)
    identity = queue.enqueue("logical-event", {"scenario": "automation"})
    claimed = queue.claim("worker-1")
    assert claimed["id"] == identity
    time["now"] = 106
    assert queue.recover() == [identity]
    assert queue.task(identity)["status"] == "uncertain"
    assert queue.claim("worker-2") is None
    # Only observe/reconcile after confirming the real fixture postcondition.
    queue.reconcile(identity, {"artifact_observed": True}, observed=True)
    assert queue.task(identity)["status"] == "completed"
    store.close()
```
