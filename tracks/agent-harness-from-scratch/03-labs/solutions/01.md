## A minimal approach

Use `Reply` for a final response and `ToolCall` for a structured request. Make a fresh `FakeProvider` for each test so its consumed script position does not leak across runs. Assert the stop reason and absence of tool effects rather than exact wording. A malformed call must be rejected before dispatch; exhaustion must remain visible rather than silently returning a canned final answer.

## A concrete test to adapt

This source example uses the delivered API. It is a starting point for a learner test, not a claim of execution. Save it in your own test file and extend its failure assertions on an approved development machine.

```python
from course_harness.providers import FakeProvider, Reply, ProviderError

def test_fake_final_and_exhaustion():
    import pytest
    provider = FakeProvider([Reply("fixture evidence")])
    messages = [{"role": "user", "content": "inspect a fixture"}]
    assert provider.complete(messages).text == "fixture evidence"
    with pytest.raises(ProviderError, match="fixture_exhausted"):
        provider.complete(messages)
    assert len(provider.requests) == 2
```
