# Lesson 4 reference solution: build and register a basic tool

Read [the lesson](../lessons/04-tool-contracts/README.md) first. Save the following example in your own `test_learner_04.py`. The functions use the delivered `Tool`, `Registry`, `object_schema`, and `Engine` APIs. They require no network, provider SDK, or agent framework.

An official provider SDK could implement lesson 3's API transport boundary. It would obtain responses from a model service. Our tool registry instead maps a returned name to an ordinary Python function. The model/SDK cannot register tools, execute handlers, or grant permission. The controller validates requests, applies host policy, and invokes only an authorized handler.

## Define one pure tool

```python
import json
import pytest

from course_harness.core import Engine, Limits
from course_harness.providers import FakeProvider, Reply, ToolCall
from course_harness.tools import Tool, Registry, Policy, object_schema

FIXTURE_ROWS = {
    "coding": ("calculator.py", "test_calculator.py"),
    "sre": ("health observation", "metric sample", "fixture log"),
    "automation": ("daily-summary event",),
}

def count_fixture_rows(arguments):
    rows = FIXTURE_ROWS[arguments["fixture"]]
    return {"fixture": arguments["fixture"],
            "count": len(rows[:arguments["limit"]])}

def make_count_tool(handler=count_fixture_rows):
    return Tool(
        name="count_fixture_rows",
        description="Count a bounded selection from a synthetic fixture",
        parameters=object_schema(
            fixture={"type": "string",
                     "enum": ["coding", "sre", "automation"], "maxLength": 16},
            limit={"type": "integer", "minimum": 0, "maximum": 8},
        ),
        execute=handler,
        effect="read",
        target="synthetic_fixture_rows",
    )
```

The result is a bounded count plus its fixture identity. The input has exactly two required fields. The integer rule intentionally rejects booleans, even though Python treats `bool` as an `int` subclass. Fixed fixture rows supply the size bound; no arbitrary list or unimplemented `maxItems` rule is assumed. Descriptions help explain a tool to the model; validation is the executable enforcement.

## Fail before registration, pass after registration

```python
def test_registration_changes_unknown_to_known():
    arguments = {"fixture": "coding", "limit": 8}
    with pytest.raises(ValueError, match="unknown tool"):
        Registry([]).prepare("count_fixture_rows", arguments)

    registry = Registry([make_count_tool()])
    selected = registry.prepare("count_fixture_rows", arguments)
    assert selected.execute(arguments) == {"fixture": "coding", "count": 2}

@pytest.mark.parametrize("fixture,count", [
    ("coding", 2), ("sre", 3), ("automation", 1),
])
def test_all_synthetic_paths(fixture, count):
    registry = Registry([make_count_tool()])
    arguments = {"fixture": fixture, "limit": 8}
    assert registry.prepare("count_fixture_rows", arguments).execute(
        arguments
    ) == {"fixture": fixture, "count": count}

def test_zero_limit_is_valid():
    arguments = {"fixture": "coding", "limit": 0}
    registry = Registry([make_count_tool()])
    assert registry.prepare("count_fixture_rows", arguments).execute(
        arguments
    )["count"] == 0
```

Registration is the deliberate source change. No dynamic discovery or generated Python is needed. On your first attempt, keep the registry empty and let the positive test fail; add the tool to make it pass.

## Prove invalid requests never execute

```python
@pytest.mark.parametrize("arguments", [
    {"fixture": "coding"},                        # missing required limit
    {"limit": 8},                                 # missing required fixture
    {"fixture": "coding", "limit": "8"},           # wrong type
    {"fixture": "coding", "limit": True},          # bool is not a count
    {"fixture": "coding", "limit": -1},            # below minimum
    {"fixture": "coding", "limit": 9},             # above maximum
    {"fixture": "production", "limit": 8},         # outside enum
    {"fixture": "coding", "limit": 8, "command": "anything"},
])
def test_invalid_requests_never_execute(arguments):
    calls = []
    def spy(validated):
        calls.append(validated)
        return count_fixture_rows(validated)
    registry = Registry([make_count_tool(spy)])
    with pytest.raises(ValueError):
        selected = registry.prepare("count_fixture_rows", arguments)
        selected.execute(arguments)
    assert calls == []
```

The final assertion establishes the boundary: an error message alone would not prove a handler had no effects. A valid but forbidden request is a different case, owned by policy rather than argument validation.

## Dispatch it through the engine and inspect the result

```python
def test_engine_dispatches_registered_tool_once():
    calls = []
    def spy(arguments):
        calls.append(arguments)
        return count_fixture_rows(arguments)

    registry = Registry([make_count_tool(spy)])
    arguments = {"fixture": "coding", "limit": 8}
    provider = FakeProvider([
        Reply(calls=(ToolCall("count-1", "count_fixture_rows", arguments),)),
        Reply("Counted synthetic rows; no side effect occurred."),
    ])
    policy = Policy("read_only", frozenset({"count_fixture_rows"}))
    result = Engine(provider, registry, policy,
                    limits=Limits(steps=2)).run("Count the fixture rows.")

    assert result.stop_reason == "final"
    assert calls == [arguments]
    assert [event["event"] for event in result.trace] == [
        "run_started", "model_called", "tool_requested", "tool_completed",
        "model_called", "run_stopped",
    ]
    requested = next(event for event in result.trace
                     if event["event"] == "tool_requested")
    assert requested["decision"] == "allow"
    tool_result = next(message for message in result.messages
                       if message["role"] == "tool")
    assert tool_result["tool_call_id"] == "count-1"
    assert json.loads(tool_result["content"]) == {
        "trust": "untrusted",
        "result": {"fixture": "coding", "count": 2},
    }
```

The engine obtains a structured request, validates it, checks policy, executes once, links the result to `count-1`, and stops after the fake's final reply. The handler remains ordinary Python. No SDK or orchestration framework participates in dispatch.

## Complete the learner extension

Add one required boolean field and an empty fixture row. The original two-field tool rejects this new argument, so your extension test fails until you update both contract and handler.

```python
EXTENDED_ROWS = {
    name: rows + ("",) for name, rows in FIXTURE_ROWS.items()
}

def count_selected_fixture_rows(arguments):
    rows = EXTENDED_ROWS[arguments["fixture"]]
    if arguments["nonempty_only"]:
        rows = tuple(row for row in rows if row)
    return {"fixture": arguments["fixture"],
            "count": len(rows[:arguments["limit"]])}

def make_extended_tool():
    return Tool(
        name="count_fixture_rows",
        description="Count selected synthetic rows",
        parameters=object_schema(
            fixture={"type": "string",
                     "enum": ["coding", "sre", "automation"], "maxLength": 16},
            limit={"type": "integer", "minimum": 0, "maximum": 8},
            nonempty_only={"type": "boolean"},
        ),
        execute=count_selected_fixture_rows,
        effect="read",
        target="synthetic_fixture_rows",
    )

def test_filter_before_counting():
    registry = Registry([make_extended_tool()])
    for flag, expected in [(False, 3), (True, 2)]:
        arguments = {"fixture": "coding", "limit": 8,
                     "nonempty_only": flag}
        selected = registry.prepare("count_fixture_rows", arguments)
        assert selected.execute(arguments)["count"] == expected
    with pytest.raises(ValueError):
        registry.prepare("count_fixture_rows",
                         {"fixture": "coding", "limit": 8,
                          "nonempty_only": "yes"})
```

Filter before slicing. As an independent next test, move the empty row to the beginning and use a limit of two; prove filtering does not consume a slot. Repeat the extension over SRE and automation fixtures. Retain the original invalid-argument cases and test that omitting the new field fails.
