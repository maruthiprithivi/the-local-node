# Lesson 10 reference solution

Read [the lesson](../lessons/10-restricted-commands/README.md) first. This reference explains the smallest intended change in the shared package; it is not a second copy of the harness.

## A minimal approach

Keep the allowed operation-to-argv mapping host-owned. Pass argv with shell disabled and use a fixed disposable cwd/environment. Assert denied operations do not reach the launch function. Verify the postcondition independently of return code and stop when the remediation ceiling/cooldown blocks repetition. The default SRE checkpoint uses synthetic state; a real subprocess cleanup extension must be clearly isolated and explicitly reviewed.

## Test the explanation

Start from the lesson's successful fixture, then change exactly one input to reach its deliberate failure. The successful result should satisfy:

Only explicitly allowed work starts; captured output stays bounded; a verified recovery finishes, while failed verification stops after the attempt ceiling.

The failure must demonstrate:

Supply shell metacharacters as an argument, then a command alias not in the allowlist. The metacharacters must never be interpreted by a shell; the unknown command must not start. Simulate restart success with unhealthy verification and require escalation.

Use pytest's `tmp_path` for mutable files/databases and a recording fake for provider/handler calls. Inject time instead of waiting. Verify a negative assertion about the boundary, such as zero executions or unchanged bytes, as well as the visible error. Never substitute “the model said it was safe” for an assertion on host policy or actual state.

## A concrete test to adapt

This source example uses the delivered API. It is a starting point for a learner test, not a claim of execution. Save it in your own test file and extend its failure assertions on an approved development machine.

```python
from course_harness.tools import run_permitted

def test_unapproved_command_does_not_start(tmp_path):
    import pytest
    with pytest.raises(PermissionError, match="allowlisted"):
        run_permitted(["unapproved-program", ";", "echo", "unsafe"],
                      allowed=frozenset(), cwd=tmp_path)
    assert list(tmp_path.iterdir()) == []

# Positive command tests belong on the learner/approved disposable worker.
# Timeout reports an uncertain effect; it is not permission to repeat.
```

```python
def run_named(name, *, approved_commands, cwd):
    from course_harness.tools import run_permitted
    if name not in approved_commands:
        raise PermissionError("unknown course-owned operation")
    argv = approved_commands[name]  # Host supplies exact argv.
    return run_permitted(argv, allowed=frozenset({tuple(argv)}),
                         cwd=cwd, timeout=2, output_limit=4096)

def verify_service(world):
    observed = world.observe({})
    if not observed["fresh"] or not observed["healthy"]:
        return {"status": "escalate", "evidence": observed}
    return {"status": "verified", "evidence": observed}
```
