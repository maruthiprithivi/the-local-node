## A minimal approach

Read the copied fixture, record its digest, propose a bounded replacement, and request approval for that exact request. Verify both intended new bytes and unchanged neighboring files. To test stale proposals, mutate the file after approval and before dispatch; the handler must reject rather than silently refresh the digest. Use a supported temporary symlink fixture and record any platform limitation honestly. Never aim the exercise at a personal checkout.

## Test the explanation

Exactly the intended toy file changes once; outside, stale, and symlink attempts produce errors without touching their targets.

The failure must demonstrate:

Use pytest's `tmp_path` for mutable files/databases and a recording fake for provider/handler calls. Inject time instead of waiting. Verify a negative assertion about the boundary, such as zero executions or unchanged bytes, as well as the visible error. Never substitute “the model said it was safe” for an assertion on host policy or actual state.

## A concrete test to adapt

This source example uses the delivered API. It is a starting point for a learner test, not a claim of execution. Save it in your own test file and extend its failure assertions on an approved development machine.

```python
from course_harness.tools import Workspace

def test_patch_preconditions(tmp_path):
    import pytest
    path = tmp_path / "calculator.py"
    old, new = "return a - b\n", "return a + b\n"
    path.write_text(old, encoding="utf-8")
    workspace = Workspace(tmp_path)
    assert "-return a - b" in workspace.preview("calculator.py", old, new)
    # A real executor must check exact Policy approval before this call.
    workspace.apply("calculator.py", old, new)
    with pytest.raises(ValueError, match="stale patch"):
        workspace.apply("calculator.py", old, "different")
    assert path.read_text(encoding="utf-8") == new
    assert workspace.originals["calculator.py"] == old
```

## Exercise extension reference

Keep this extension in your learning branch. The fragment demonstrates the minimal additional seam; integrate it only after the baseline test and deliberate-failure case are understood.

```python
from course_harness.tools import Tool, object_schema, Policy, Workspace

def approved_patch(workspace, policy, path, expected, replacement):
    tool = Tool("workspace_patch", "Apply one reviewed toy patch",
        object_schema(path={"type": "string", "maxLength": 256},
                      expected={"type": "string", "maxLength": 2048},
                      replacement={"type": "string", "maxLength": 2048}),
        lambda args: workspace.apply(args["path"], args["expected"],
                                     args["replacement"]),
        effect="write", target=str(workspace.root))
    from course_harness.tools import Registry
    arguments = {"path": path, "expected": expected, "replacement": replacement}
    Registry([tool]).prepare(tool.name, arguments)
    if policy.decide(tool, arguments) != "allow":
        return {"status": "approval_required_or_denied", "tool": tool,
                "arguments": arguments}
    tool.execute(arguments)
    return {"status": "completed"}

def test_exact_patch_approval(tmp_path):
    path = tmp_path / "toy.py"
    path.write_text("old", encoding="utf-8")
    workspace = Workspace(tmp_path)
    policy = Policy("semi", frozenset({"workspace_patch"}))
    pending = approved_patch(workspace, policy, "toy.py", "old", "new")
    assert path.read_text(encoding="utf-8") == "old"
    policy.approve(pending["tool"], pending["arguments"])
    assert approved_patch(workspace, policy, "toy.py", "old", "new")["status"] == "completed"

# Keep deny and ask distinct in a richer wrapper; neither invokes execute.
# This teaching wrapper does not create OS isolation or eliminate file races.
```
